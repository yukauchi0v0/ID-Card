# Cloud Save & Publishing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let signed-in users keep their ID Card in the cloud (edit on any device) and publish it to a short, public viewer URL backed by Supabase.

**Architecture:** The static site stays static. Studio gets a Supabase client (vendored UMD bundle), email magic-link auth, and a cloud module that saves the draft row + Storage assets and publishes an immutable `card_versions` snapshot. Viewer reads only `get_public_card(code)` via PostgREST RPC, falling back to the legacy static `card.json` path. RLS on `profiles`/`cards`/`card_versions` and Storage policies enforce ownership; AR engine and in-browser compilation are untouched.

**Tech Stack:** Vanilla ES modules (no build step), A-Frame 1.5.0 + MindAR 1.2.2 (existing), Supabase (Postgres, Storage, Auth magic link), vendored `supabase-js` 2.119.2 UMD, Node `node:test` for pure-function tests.

**Spec:** `docs/superpowers/specs/2026-11-24-cloud-save-design.md`

## Global Constraints

- No build step; every script is served as-is from GitHub Pages; all first-party comments are Traditional Chinese.
- Only public values may reach the browser: `SUPABASE_URL` and the publishable key `sb_publishable_xlh3Dj0Se4wcqSo5GA4dFQ_X34GUr4u`. Never add a `service_role` key.
- Project URL: `https://wvtkvtomfzhgmmlaxyuj.supabase.co`.
- Auth is email magic link only; one account = one card (`cards.user_id` unique).
- `card_code` is 8 characters from alphabet `abcdefghijkmnpqrstuvwxyz23456789`, generated by the database, never by the client. Display name may be Chinese and never appears in the URL; changing it never changes the URL.
- Upload limits (enforced in browser and mirrored by bucket limit 62914560 bytes): cover 2 MB each (max 8), photo 8 MB, video 60 MB, PDF 15 MB, whole card 150 MB.
- Viewer URL shape: `viewer.html?card=<code>`; the legacy `?card=cards/<slug>/card.json` form must keep working.
- AR behaviour (`js/ar/*`, `js/media/*`) must not change; compilation still happens in the browser before publishing.
- Every task ends with `node --check` on touched files and a commit; run `npm.cmd test` (PowerShell blocks `npm.ps1`).

## Review Focus

- A signed-out visitor opening `studio.html` must still be able to try the editor, and every action that needs the cloud must show a sign-in prompt instead of failing silently.
- A user whose card has no published version must get a readable "not published yet" message in the viewer, not a blank page or a JSON error.
- Someone else's `card_code` typed into `?card=` must show their published card (public read), while saving to it must be impossible.
- Revisiting the magic link (link preview bots, back button) must not lose the session or bounce between auth states forever.
- A user at the storage limit (large video) must be told which field is too big before upload starts, not after a 40-second compile.

```js
import { SUPABASE_KEY, SUPABASE_URL } from "../config.public.js";
let client;
export function isCloudConfigured() { return Boolean(window.supabase && window.supabase.createClient); }
export function getClient() {
  if (!isCloudConfigured()) return null;
  if (!client) client = window.supabase.createClient(SUPABASE_URL, SUPABASE_KEY, { auth: { persistSession: true, detectSessionInUrl: true, flowType: "pkce" } });
  return client;
}
```

- [ ] **Step 5: Implement the Supabase calls**

`saveDraft` uploads changed blobs with `storage.from("card-assets").upload(path, blob, { upsert: true, contentType })`, then `from("cards").upsert({ user_id: userId, profile, settings, targets, signature, mind_path, updated_at: new Date().toISOString() }, { onConflict: "user_id" })`.
